O utPLSQL permite testes sem descrição e exibe o nome do procedimento no relatório. Esta regra impõe uma convenção de legibilidade: todo teste efetivo deve ter uma descrição compreensível.

Código em desconformidade

CREATE PACKAGE test_pkg AS
  --%suite
  --%test
  PROCEDURE creates_customer;
END test_pkg;

Código correto

CREATE PACKAGE test_pkg AS
  --%suite
  --%test(Retorna o cliente quando ele existe)
  PROCEDURE creates_customer;
END test_pkg;

Um %displayname(descrição) efetivo também fornece a descrição do teste, mas prefira %test(descrição), pois o utPLSQL documenta %displayname como redundante e possivelmente removível.
