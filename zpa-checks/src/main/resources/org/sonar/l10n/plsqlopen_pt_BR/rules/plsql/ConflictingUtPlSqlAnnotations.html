O utPLSQL aceita algumas anotações só uma vez por suíte, contexto ou procedure. Para uma repetida, ele mantém a primeira e avisa sobre as outras, e uma procedure anotada com %test não pode ser também uma procedure de preparação ou limpeza: o utPLSQL ignora o %beforeall, %afterall, %beforeeach ou %aftereach nela. O pacote compila, mas a anotação ignorada não faz nada.

Esta regra reporta uma anotação repetida que o utPLSQL aceita só uma vez no seu escopo, e uma anotação de preparação ou limpeza numa procedure %test. Várias procedures distintas anotadas com %beforeall, %afterall, %beforeeach, %aftereach, %beforetest ou %aftertest são válidas e não são reportadas.

Exemplo de código não conforme

create package crate_test as
  --%suite
  --%test(Creates a crate)
  --%test(Creates a crate with a label) -- Noncompliant
  procedure creates_crate;
end;

Solução conforme

create package crate_test as
  --%suite
  --%test(Creates a crate)
  procedure creates_crate;
end;
