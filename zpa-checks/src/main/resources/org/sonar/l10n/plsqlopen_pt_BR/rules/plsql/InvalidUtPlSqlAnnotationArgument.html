Corrija os argumentos inválidos das anotações utPLSQL. O PL/SQL pode ser compilado com sucesso enquanto o utPLSQL ignora um valor inválido ou um argumento malformado.

Por que isso importa

O utPLSQL valida determinados valores das anotações ao construir a suíte de testes. Um argumento inválido pode impedir silenciosamente que uma suíte, teste, tag, política de rollback ou exceção esperada seja aplicada.

Os nomes das tags não podem começar com hífen, conter espaços ou os caracteres de expressão (, ), &, | ou !. As palavras reservadas none e any não são nomes literais de tags.

Exemplos

--%suitepath(foo bar)       -- Caminho inválido
--%rollback(transactional)  -- Apenas auto e manual são suportados
--%tags(-fast)              -- Uma tag não pode começar com '-'
--%throws                   -- Uma exceção esperada é necessária
