O utPLSQL verifica os valores de algumas anotações enquanto monta a suíte, e ignora um valor inválido sem aviso: um suitepath, um modo de rollback, uma tag ou uma exceção esperada deixa então de ser aplicado, embora o pacote compile.

Esta regra reporta um argumento ausente ou inválido de %suitepath, %rollback, %tags e %throws. Um suitepath é uma lista de nomes separados por pontos, sem espaços; o %rollback aceita auto ou manual; uma tag não pode começar com hífen, conter espaços ou os caracteres (, ), &, |, !, nem ser uma das palavras reservadas none e any; o %throws precisa de uma exceção.

Exemplo de código não conforme

create package crate_test as
  --%suite
  --%suitepath(warehouse crates) -- Noncompliant
  --%rollback(transactional) -- Noncompliant

  --%test(Creates a crate)
  --%tags(-fast) -- Noncompliant
  procedure creates_crate;
end;

Solução conforme

create package crate_test as
  --%suite
  --%suitepath(warehouse.crates)
  --%rollback(manual)

  --%test(Creates a crate)
  --%tags(fast)
  procedure creates_crate;
end;
