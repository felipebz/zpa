Numa consulta sobre duas ou mais tabelas, uma coluna escrita sem a sua tabela ou alias depende das colunas de todas as tabelas da cláusula FROM. A consulta funciona enquanto só uma delas tem uma coluna com esse nome. Quando uma coluna com o mesmo nome é acrescentada a outra das tabelas, o Oracle rejeita a consulta com o ORA-00918 ("column ambiguously defined"), e uma unidade PL/SQL que a contém fica inválida. O leitor também precisa conhecer as colunas de todas as tabelas para saber de onde vem o valor.

Esta regra reporta uma coluna da lista do SELECT escrita sem tabela ou alias, numa consulta cuja cláusula FROM lê duas ou mais tabelas, views ou subconsultas, separadas por vírgulas ou unidas por qualquer JOIN ou APPLY. Uma coluna da lista de um JOIN … USING não é reportada: o Oracle rejeita um qualificador nela (ORA-25154). Uma consulta com NATURAL JOIN não é verificada: o Oracle rejeita um qualificador nas colunas que ele compartilha (ORA-25155), e quais são depende das colunas das duas origens. Um nome que uma variável ou parâmetro PL/SQL assume, e pseudocolunas como ROWNUM, LEVEL ou SYSDATE, não são reportados.

Exemplo de código não conforme

select code, -- Noncompliant
       r.label
  from crate c, rack r
 where r.id = c.rack_id;

Solução conforme

select c.code,
       r.label
  from crate c, rack r
 where r.id = c.rack_id;
