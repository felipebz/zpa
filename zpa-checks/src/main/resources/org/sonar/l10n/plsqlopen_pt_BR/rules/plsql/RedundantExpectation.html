Uma expectativa do utPLSQL compara o valor obtido com o esperado: ut.expect(actual).to_equal(expected). Quando os dois argumentos são a mesma expressão, a expectativa compara um valor com ele mesmo e sempre passa: o teste não verifica nada, em geral por causa de um copiar e colar.

Esta regra reporta um ut.expect(...) cujo valor obtido é a mesma expressão que o primeiro argumento do seu matcher, em código de teste.

Exemplo de código não conforme

create package body crate_label_test is
  procedure formats_the_code is
    l_expected varchar2(20) := 'CR-0042';
    l_actual varchar2(20);
  begin
    l_actual := crate_label(42);
    ut.expect(l_actual).to_equal(l_actual); -- Noncompliant
  end;
end;

Solução conforme

create package body crate_label_test is
  procedure formats_the_code is
    l_expected varchar2(20) := 'CR-0042';
    l_actual varchar2(20);
  begin
    l_actual := crate_label(42);
    ut.expect(l_actual).to_equal(l_expected);
  end;
end;
