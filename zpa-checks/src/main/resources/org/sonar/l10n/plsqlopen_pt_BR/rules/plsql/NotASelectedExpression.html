Num SELECT DISTINCT, as linhas são tornadas distintas antes de serem ordenadas, então o ORDER BY só pode usar o que cada linha distinta tem: as expressões selecionadas, os seus aliases e expressões feitas delas. Uma coluna que não é selecionada não tem um único valor por linha, também quando uma expressão selecionada a usa: com SELECT DISTINCT UPPER(r.label), ORDER BY r.label é rejeitado. O Oracle rejeita uma consulta assim com o ORA-01791 ("not a SELECTed expression"). Versões antigas aceitavam algumas dessas consultas, que passam a falhar depois de uma atualização.

Esta regra reporta uma expressão do ORDER BY de um SELECT DISTINCT que usa uma coluna da consulta que não é selecionada. Uma expressão selecionada é reconhecida como o Oracle a compara: nomes sem aspas sem diferenciar maiúsculas de minúsculas, uma coluna com ou sem o nome da sua tabela ou alias, e sem considerar parênteses, espaços e comentários. Uma expressão feita de expressões selecionadas, aliases, literais, funções, nomes PL/SQL e valores como SYSDATE é aceita (ORDER BY LOWER(alias)), assim como uma posição (ORDER BY 1). Uma consulta que seleciona * não é verificada.

Exemplo de código não conforme

select distinct r.label
  from rack r
 order by r.capacity; -- Noncompliant

Solução conforme

select distinct r.label, r.capacity
  from rack r
 order by r.capacity;
