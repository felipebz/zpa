Um SELECT ... INTO precisa retornar exatamente uma linha: sem nenhuma linha ele lança NO_DATA_FOUND, e com mais de uma, TOO_MANY_ROWS. Quando nada as trata, a exceção encerra o trabalho de quem chamou com um erro que não diz qual busca falhou, muitas vezes longe da consulta que o causou.

Esta regra reporta um SELECT ... INTO cujo bloco não tem tratador de exceção. Uma consulta escrita num tratador de exceção não é coberta pelos tratadores ao lado dela: só um bloco em volta conta. Um BULK COLLECT INTO não é reportado, nem uma consulta que sempre retorna uma linha: uma única agregação (COUNT, SUM, AVG, MIN, MAX) sem GROUP BY, HAVING, operadores de conjunto, cláusula de limitação de linhas ou MODEL. A regra não verifica quais exceções o tratador nomeia.

Com o parâmetro strict igual a false, um tratador de qualquer bloco ou subprograma em volta cobre a consulta.

Exemplo de código não conforme

create function rack_label(p_rack number) return varchar2 is
  l_label rack.label%type;
begin
  select label into l_label from rack where id = p_rack; -- Noncompliant
  return l_label;
end;

Solução conforme

create function rack_label(p_rack number) return varchar2 is
  l_label rack.label%type;
begin
  select label into l_label from rack where id = p_rack;
  return l_label;
exception
  when no_data_found then
    return null;
end;
