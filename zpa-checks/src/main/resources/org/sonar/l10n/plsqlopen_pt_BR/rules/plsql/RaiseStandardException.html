Exceções predefinidas como NO_DATA_FOUND ou TOO_MANY_ROWS dizem que uma operação específica falhou. Lançar uma explicitamente faz o código mentir sobre o que aconteceu: um tratador feito para uma busca que falhou captura uma condição de negócio, e muitas vezes isso significa que uma exceção é usada como um salto para o tratador em vez de um fluxo de controle simples.

Esta regra reporta um RAISE de uma exceção predefinida do STANDARD (NO_DATA_FOUND, TOO_MANY_ROWS, VALUE_ERROR, ZERO_DIVIDE, DUP_VAL_ON_INDEX, INVALID_NUMBER...). Use o fluxo de controle, ou uma exceção definida pelo usuário ou RAISE_APPLICATION_ERROR que nomeie a condição.

Exemplo de código não conforme

create function rack_is_full(p_rack in number) return boolean is
  l_free number;
begin
  select capacity - used into l_free from rack where id = p_rack;
  if l_free = 0 then
    raise too_many_rows; -- Noncompliant
  end if;
  return false;
exception
  when too_many_rows then
    return true;
end;

Solução conforme

create function rack_is_full(p_rack in number) return boolean is
  l_free number;
begin
  select capacity - used into l_free from rack where id = p_rack;
  return l_free = 0;
end;
