A column under an enabled NOT NULL constraint, or part of a primary key, never holds null. An IS NULL condition on it is always false, so a WHERE that requires it selects no row, and an IS NOT NULL condition on it is always true and filters nothing. Either the condition is useless, or it tests a different column than the one intended.

This rule uses the table and view metadata read from the database, and reports nothing without it. A column is reported only when the database guarantees that no row holds null: a NOT NULL constraint that is disabled, NOVALIDATE or deferrable does not count, and neither does a CHECK constraint. A column read from the side of an outer join that has no matching row is null even when the table does not allow it, so it is never reported.

Noncompliant Code Example

-- shipments.tracking_code is declared NOT NULL
select count(*)
  into pending
  from shipments
 where tracking_code is null;

Compliant Solution

select count(*)
  into pending
  from shipments
 where delivered_on is null;
