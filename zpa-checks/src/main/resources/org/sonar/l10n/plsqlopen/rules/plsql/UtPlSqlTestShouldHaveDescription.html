utPLSQL allows a test without a description and displays the procedure name in its report. This rule enforces a readability convention: every effective test should have a human-readable description.

Noncompliant Code Example

CREATE PACKAGE test_pkg AS
  --%suite
  --%test
  PROCEDURE creates_customer;
END test_pkg;

Compliant Solution

CREATE PACKAGE test_pkg AS
  --%suite
  --%test(Returns the customer when it exists)
  PROCEDURE creates_customer;
END test_pkg;

A current effective %displayname(description) also supplies the test description, but %test(description) is preferred because utPLSQL documents %displayname as redundant and potentially removable.
