When the analyzer cannot parse part of a file, it cannot analyze that part: the other rules report nothing in it, and the rules that need to see a whole scope, such as those about unused or hidden declarations, may report nothing in the rest of the file either. A file that does not parse therefore hides its issues.

This rule reports where the parser failed, so that the files that do not parse can be counted and fixed. With error recovery, each piece of code the parser skipped is reported; without it, the line where parsing stopped, with the parser's message. The cause is either code Oracle also rejects, or syntax the analyzer does not support yet, which is worth reporting to the project.
