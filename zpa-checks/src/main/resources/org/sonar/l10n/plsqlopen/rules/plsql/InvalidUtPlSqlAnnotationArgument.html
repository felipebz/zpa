Fix invalid utPLSQL annotation arguments. The PL/SQL can compile successfully while utPLSQL ignores an invalid value or malformed argument.

Why this matters

utPLSQL validates selected annotation values while building the test suite. An invalid argument can therefore silently prevent a suite, test, tag, rollback policy, or expected exception from being applied.

Tag names cannot start with a dash, contain whitespace or the expression characters (, ), &, |, or !. The reserved words none and any are not literal tag names.

Examples

--%suitepath(foo bar)       -- Invalid path
--%rollback(transactional)  -- Only auto and manual are supported
--%tags(-fast)              -- A tag cannot start with '-'
--%throws                   -- An expected exception is required
