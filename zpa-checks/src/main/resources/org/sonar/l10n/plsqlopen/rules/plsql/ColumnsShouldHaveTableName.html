In a query over two or more tables, a column written without its table or alias depends on the columns of every table in the FROM clause. The query works while only one of them has a column of that name. Once a column of the same name is added to another of the tables, Oracle rejects the query with ORA-00918 ("column ambiguously defined"), and a PL/SQL unit that holds it becomes invalid. The reader also has to know every table's columns to tell where the value comes from.

This rule reports a column of the select list written without a table or alias, in a query whose FROM clause lists two or more tables, views or subqueries separated by commas; queries written with JOIN are not checked. A name a PL/SQL variable or parameter takes, and pseudocolumns such as ROWNUM, LEVEL or SYSDATE, are not reported.

Noncompliant Code Example

select code, -- Noncompliant
       r.label
  from crate c, rack r
 where r.id = c.rack_id;

Compliant Solution

select c.code,
       r.label
  from crate c, rack r
 where r.id = c.rack_id;
